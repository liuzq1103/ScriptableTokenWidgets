通过本机 Magpie 请求 `zhipu/glm-5.3`，路由响应确认实际提供方为 `zhipu`、模型为 `zhipu/glm-5.3`。已获得完整最终报告。以下是人工核实后的摘要：

| 结论 | 触发与影响 | 处理 |
|---|---|---|
| 已确认 | 服务运行时重装只更新任务定义，旧 Node 进程继续使用旧代码或配置 | 重装调用重启流程，并在创建网络入口前验证带鉴权的本机 API |
| 已确认 | 默认转发模式与防火墙模式之间直接切换会留下旧入口 | 在修改配置和任务前阻止直接切换；要求先卸载当前模式 |
| 已确认，取决于环境 | 安装器和运行脚本选择 Node 的顺序不同，多版本环境下程序路径可能不一致 | 配置记录实际 `process.execPath`，任务和防火墙使用同一可执行文件 |
| 已排除 | 怀疑额度 `used` 可能为计数，导致百分比方向错误 | Magpie 官方 `QuotaSpan` 明确规定其单位为百分比，保留当前计算 |

额度单位依据：[Magpie provider/quotas.go](https://github.com/yetone/magpie/blob/main/internal/provider/quotas.go)。GLM 未在本次输入范围内发现确定的 Token 算术、日期或隐私过滤缺陷；这不构成完整正确性保证。

人工补充发现并修复：端口变化后卸载应依据保存的旧端口，重新安装应迁移原有项目转发；遇到其他目标或被修改的转发则保留并报错。
